# 编码计划：PDF → Markdown 解析模块（v2）

## 目标概述

将财报/公告类**文本型 PDF** 解析为结构化 Markdown，为后续 Step 2（分块）和 Step 3（DeepSeek 摘要）做准备。新增 `core/data/pdf_parser.py` 模块，与现有 `pdf_split.py`（按页数物理分割）职责分离。

- 项目代码已 clone，工作区干净（`git status` 无未提交变更）

    - 普通公告（纯文本，无表格）
    - 含有线表格的财报（如半年报）
    - 含合并单元格/跨页表格的年报

## 契约定义（抽象层）

### 4.1 数据结构 — `core/data/models.py`（扩展现有文件）

```python
"""PDF 解析结果的数据模型"""
from __future__ import annotations

from dataclasses import dataclass, field

@dataclass(frozen=True)
class ParsedPage:
    """单页 PDF 解析结果。

    Attributes:
        page_number: 1-based 页码。
        text: 该页提取的 Markdown 文本。
        tables: 该页检测到的表格元信息列表，每项含 bbox/row_count/col_count。
        toc_items: 指向该页的目录条目列表，格式 [level, title, page_number]。
        metadata: 文档级元数据（file_path, page_count 等），来自 pymupdf4llm。
    """
    page_number: int
    text: str
    tables: list[dict] = field(default_factory=list)
    toc_items: list[list] = field(default_factory=list)
    metadata: dict = field(default_factory=dict)

@dataclass(frozen=True)
class ParsedDocument:
    """整份 PDF 文档的解析结果。

    Attributes:
        source: 来源标识（文件路径或公告标题）。
        pages: 按页码排列的解析结果列表。
        total_pages: 文档总页数。
    """
    source: str
    pages: list[ParsedPage]
    total_pages: int

    @property
    def full_text(self) -> str:
        """拼接所有页面的 Markdown 文本，页间用分隔符隔开。"""
        return "\n\n---\n\n".join(p.text for p in self.pages if p.text.strip())
```

```jsx
core/data/pdf_parser.py
```

## 技术决策说明

### 为什么新建 `pdf_parser.py` 而不是修改 `pdf_split.py`？

**职责分离**。现有 `pdf_split.py` 负责按页数物理分割大文件（输入 PDF → 输出多个子 PDF），新模块负责内容提取（输入 PDF → 输出 Markdown）。两者在数据流中是不同阶段：

```jsx
大文件 PDF → pdf_split.py 分割 → 子 PDF → pdf_parser.py 解析 → Markdown → Step 2 分块
小文件 PDF → 直接 → pdf_parser.py 解析 → Markdown → Step 2 分块
```

### 为什么主函数是 async？

虽然 `pymupdf4llm.to_markdown()` 本身是同步的，但：

1. 与项目现有的异步架构一致（全链路 async/await）
2. 后续可轻松加入 `asyncio.to_thread()` 将 CPU 密集的 PDF 解析放到线程池
3. 调用方（如 `announcements_data_handler.py`）本身就是异步的

### 为什么 `ignore_images=True`？

财报/公告类文本型 PDF 中的图片通常是公司 logo、印章等装饰性内容，对摘要无价值。忽略图片可以：

- 减少输出 Markdown 体积
- 加速解析
- 避免 base64 图片数据污染下游 LLM prompt

### `header=False, footer=False` 的注意事项

此参数**仅在安装 pymupdf-layout 后生效**。未安装时 PyMuPDF4LLM 会忽略此参数。`_clean_markdown()` 中的页码清理逻辑作为兜底方案。

> ⚠️ **待验证**：如果 `pymupdf-layout` 的页眉页脚过滤效果好，可考虑后续安装。但 layout 包引入 ML 模型，需评估在 i3 Mac Mini 上的性能影响。
