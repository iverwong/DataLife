# 重构安全检查清单

在执行重构计划之前，逐项检查以下要素，确保重构有足够的安全网。

## 基线确认
- [ ] 当前分支工作区干净（无未提交变更）
- [ ] 全量测试已运行并记录基线结果（总数 / 通过数）
- [ ] 所有测试均通过（基线为全绿）
- [ ] basedpyright 零 error / 零 warning
- [ ] ruff check 零 error

## 测试覆盖评估
- [ ] 目标模块是否有对应的测试文件？
- [ ] 测试是否覆盖主要代码路径？
- [ ] 外部依赖是否已通过 mock/fixture 隔离？
- [ ] 计划中需要补充的测试是否已全部编写？
- [ ] 补充的测试在当前代码上是否全部通过？

## 风格基线提取
- [ ] 命名约定（类名、函数名、变量名、常量名、模块名）
- [ ] Import 组织方式（分组、排序、`from __future__`）
- [ ] 类型标注风格（`X | None` vs `Optional[X]`、`list[X]` vs `List[X]`）
- [ ] Docstring 风格（Google / NumPy / reST）和语言（中文 / 英文）
- [ ] 异常类命名和组织模式
- [ ] 日志库和使用约定

## 影响范围确认
- [ ] 已识别所有直接修改的文件
- [ ] 已识别所有间接影响的文件（调用方、依赖方）
- [ ] 高风险变更点是否有明确的处理策略？
- [ ] 跨模块接口变更是否在计划中列出？

## 每步执行后检查
- [ ] 所有测试通过（与基线对比无回归）
- [ ] basedpyright 零 error / 零 warning
- [ ] ruff check 零 error
- [ ] 代码风格与项目一致
- [ ] 未引入新功能或业务逻辑变更
- [ ] Git commit message 格式正确（refactor: <手法> - <描述>）

## 最终验证
- [ ] 全量测试通过，测试总数 ≥ 基线
- [ ] basedpyright 全项目零 error / 零 warning
- [ ] ruff check 全项目零 error
- [ ] 重构目标达成
- [ ] 所有「范围外发现」已记录
- [ ] 所有「接口影响」已记录
